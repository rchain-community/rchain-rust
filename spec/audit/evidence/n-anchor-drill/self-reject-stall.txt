== a self-created block failing its own validation stalls three of four nodes at one height ==

**A raw capture**, taken 2026-10-10 on an idle box (24 cores, no builds running; the machine's load
was its desktop, and no containers were up before this). Command:

    tools/devnet.sh down -v
    tools/devnet.sh up --validators 4 --fresh          # autopropose on, default epoch length

The rig never converged, and the reason is not the joiners: three of the four nodes each **reject their
own block at height 49**, repeatedly, while the fourth (validator 1) passes it and runs away.

== the causal chain, as far as it is measured ==

1. **Four fringe keys are recorded with two different states each**, on every node, in normal operation —
   no injection, no fault, no byzantine actor. The signal's own text says what happens next: *the smaller is
   kept*, so the **value at those keys changes** from what a node had computed when it built its block.
2. **Within seconds, the node's own block fails its own validation** — *"the block's declared pre-state hash
   is not the state this node computed from its justifications — this node's view of the parents differs from
   the proposer's, so the disagreement is about the merge rather than about the block's deploys"*. For a
   self-created block, "the proposer" is this node: it computed the pre-state when it built the block, and
   recomputes a different one when it validates it.
3. **The proposer counts it as a failure and halts autopropose** — the code says so in the arm that fired
   (`proposer.rs`: *"count it so the caller can halt autopropose"*) — so the node stops producing at that
   height. Measured: three of four nodes stop at height **49** (45, 46, 49), the fourth passes it and runs
   to 133, and the four heights never meet again.
4. The net therefore diverges into four heads **with nobody at fault**, and finality cannot advance (88-101
   `finality did not advance` lines per node).

**The boundary of the claim.** (1), (2) and the ordering are measured, on all four nodes, with the logs
above. (3) is the code's own stated intent plus the heights. What is **inferred** is that the tie-broke keys
are what the *merge* for block #49 consulted — the hashes cannot be compared directly, because a pre-state is
a merge result over many records and not one record's value. Proving it needs one instrumented run: log the
tie-break's decision and whether that key is read while building the block whose validation then fails.
